# P2PMessenger 0.2

Локальная версия для Android 10+ (minSdk 29, target/compileSdk 35).
applicationId: kz.p2pmessenger. versionCode: 2, versionName: 0.2.

## Использование

1. Установите версию 0.2 на два телефона и подключите их к одной Wi-Fi сети.
2. Откройте приложение на обоих телефонах. В разделе «Устройства в сети» появится второй телефон.
3. Нажмите на устройство: его адрес появится в поле IP. Введите сообщение и отправьте.
4. При необходимости нажмите «Обновить». Ручной ввод IP доступен как резервный способ, в том числе для связи с версией 0.1.

NSD/mDNS используется только для обнаружения. Сообщения по-прежнему передаются через LanMessenger по TCP, порт 45888, UTF-8, одна строка на соединение. Устройства с другим объявленным портом не предлагаются для выбора. Старое приложение 0.1 не объявляет NSD-сервис и автоматически не обнаруживается.

Тип сервиса: `_p2pmessenger._tcp.`. Имя включает модель телефона и случайный суффикс. TXT `id` исключает собственный сервис даже при переименовании Android. Поиск и регистрация активны, пока экран приложения видим; при уходе с экрана освобождаются. TCP-сервер работает один раз на процесс приложения. Фоновая работа после завершения процесса ОС не гарантируется.

## Сборка

Нужны JDK 17, Gradle 8.9, Android SDK 35. Укажите SDK через ANDROID_HOME или локальный local.properties.

```text
gradle assembleDebug testDebugUnitTest lintDebug
```

APK: app/build/outputs/apk/debug/app-debug.apk.
Исходный `.github/workflows/build-apk.yml` сохранён без изменений. Публикация и запуск GitHub Actions не выполнялись.

## Проверка на двух телефонах (требует реальных устройств)

- После запуска оба телефона видят друг друга, но не себя.
- Выбор второго телефона позволяет отправить и получить сообщения в обе стороны; проверить кириллицу и emoji.
- Два телефона одной модели показываются как разные устройства.
- Поворот экрана и сворачивание/возврат не создают второй TCP-сервер; после возврата обнаружение возобновляется.
- «Обновить» несколько раз: нет дублей устройств и аварийного завершения.
- Закрытие приложения на втором телефоне или отключение его Wi-Fi удаляет устройство после уведомления NSD (не обязательно мгновенно); поздний resolve не возвращает потерянное устройство.
- Выключение/включение Wi-Fi, возврат в приложение и «Обновить» восстанавливают список.
- При недоступном mDNS ручной IP продолжает работать; проверить отдельно обмен 0.2 ↔ 0.1.

Гостевые сети и изоляция клиентов маршрутизатора могут препятствовать обнаружению и/или TCP. Оба приложения должны быть открыты для проверки NSD. Автотесты TCP и успешная компиляция не заменяют эту проверку.

## Разбор исходной версии и изменения

Изучены все исходные файлы: три Kotlin-класса, Manifest, два XML-ресурса, Gradle-конфигурация, README, .gitattributes и GitHub workflow.

- LanMessenger.kt: исходные ServerSocket/Socket, порт и построчный протокол оставлены побайтно без изменений.
- Peer.kt: исходная модель name/host/port использована в списке найденных устройств, без изменений.
- MainActivity.kt: добавлены список, выбор устройства, обновление и статусы NSD; ручной IP сохранён. Выбранное исчезнувшее устройство блокирует отправку до повторного обнаружения либо ручного редактирования IP.
- NsdDiscovery.kt: новый модуль регистрации, поиска, последовательного resolve, удаления потерянных сервисов и защиты от поздних callback. Обновления UI выполняются на главном потоке. Используется API, совместимый с Android 10; deprecated resolveService сохранён намеренно для minSdk 29.
- MessengerApplication.kt и Manifest: один LanMessenger на процесс вместо нового экземпляра при каждом пересоздании Activity; существующие разрешения сохранены.
- app/build.gradle.kts: версия 0.2/2 и JUnit для регрессионных TCP-тестов. applicationId и версии SDK/плагинов не менялись.
- styles.xml, strings.xml, корневой Gradle, settings, gradle.properties, .gitattributes и workflow сохранены.
- .gitignore: исключены локальные SDK-настройки, кэши и результаты сборки.

Унаследованные ограничения 0.1: LanMessenger подавляет сетевые ошибки, не подтверждает доставку, не шифрует сообщения; история хранится в памяти экрана. Запись «Я: …» означает попытку отправки, а не подтверждение доставки. Эти свойства транспорта в 0.2 не изменены.

Справочник NSD: https://developer.android.com/develop/connectivity/wifi/use-nsd
